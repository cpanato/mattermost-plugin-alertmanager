# v0.5.0-rc.1

This is a pre-release for testing the revived Prometheus Alertmanager plugin.
The previous stable release is v0.4.0; report regressions before promoting 0.5.0.

## Compatibility changes

- Requires Mattermost **11.7 or later**. This release does not support old 7.x–10.x servers.
- Building requires Go **1.27+**, Node **24**, and npm **10+**.
- Plugins still use the ID `alertmanager`; existing configuration keys are preserved.

## Changes

- Migrate to the public Mattermost SDK v0.6.0 and Alertmanager v0.34.1.
- Remove unused frontend dependencies and Node crypto polyfills; generate tokens with browser crypto.
- Replace the legacy modal with a native dialog for React 18/19 hosts.
- Fix configuration cloning, initial activation, concurrent channel lookup and immutable settings updates.
- Return retryable webhook failures when posting fails; fix canceled response bodies and retry cleanup.
- Include the token-comparison fix already on main since v0.4.0. Tokens must be passed without added quotes; regression tests verify routing to the correct channel with multiple configurations.
- Build static server binaries and exclude macOS archive metadata from plugin bundles.
- Provide Docker setup, automatic smoke tests, CI integration tests and updated documentation.
- Require a successful npm installation stamp before reusing dependencies in make targets.
- Show positive remaining durations for silences and distinguish pending start times; reject malformed silence actions without panicking.

## Validation and remaining scope

Upload/activation and firing/resolved delivery were tested on Mattermost 11.7.14
and 12.0.0. Go race tests, lint and five-platform bundle builds passed.
Silence expiration was additionally checked on both versions through the slash
command and the Mattermost post-action API, including removal of the button.
The status command was checked against the running Alertmanager version.
Browser checks passed on the React 18 and React 19 hosts for configuration
creation/editing, token generation, save/reload persistence and confirmed
deletion. Activation after restart was verified on the ESR.

Basic authentication is still not supported in dedicated settings (issue #7).
Custom templates, severity-based colors and plugin-side HA deduplication remain
future work. TLS timeouts reported against private deployments need reproduction;
this pre-release is not a general TLS/network fix.
